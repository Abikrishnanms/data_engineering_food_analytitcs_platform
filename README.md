**FoodFlow** is an end-to-end data engineering and conversational analytics platform engineered to process, validate, model, and analyze **2,294,057 real-world food delivery records**. The platform takes raw, multi-table CSV datasets through an automated ETL pipeline into a normalized PostgreSQL warehouse, exposes pre-aggregated analytical data models governed by a strict analytics contract, serves an interactive multi-page Streamlit & Plotly dashboard, and features a dual-mode, 5-tier secured Natural Language Query (NLQ) engine ("Ask FoodFlow AI").

Every number presented in the dashboard or generated by the AI engine reconciles to audited SQL views over real data—with zero mocked metrics, zero direct table queries, and guaranteed join safety.

## 1. Platform Overview 

Modern analytics platforms frequently suffer from data drift, broken metrics contracts, SQL injection risks in AI features, and slow aggregation queries over millions of records. FoodFlow was architected to solve these fundamental engineering challenges:

- **100% Data Integrity:** Every raw dataset undergoes 16 automated quality checks (referential integrity, numeric boundaries, enum validation, timestamp formats) before ingestion into PostgreSQL.
- **Strict Analytics Contract:** Downstream applications (Streamlit dashboard and NLQ) are decoupled from transactional tables. They query exclusively through tested, pre-aggregated views and functions, preventing row-multiplication bugs when joining one-to-many relationships.
- **Dynamic Non-Additive Aggregations:** Non-additive metrics such as Average Order Value (AOV), distinct active counts, and cancellation rates are dynamically calculated via stored procedures (`fn_kpi_summary`), avoiding invalid averages of averages.
- **Sub-Minute Bulk Ingestion:** Utilizing PostgreSQL binary streaming `COPY ... FROM STDIN` via `copy_expert()`, the pipeline ingests all 2.29M+ rows in under 25 seconds.
- **Production-Safe AI Analytics:** The NLQ translation layer features strict AST validation, regex write-blockers, single-statement enforcement, a strict view allowlist, and executes under a dedicated read-only role with a 10-second statement timeout cap.

The relational schema represents an enterprise multi-vendor food delivery ecosystem across 5 normalized entities:

```

                              │                           │
                              │                           │
                              ▼                           ▼
                         order_items >──────────────── menu
```

### Table Specifications & Record Counts

| Table | Exact Records | Primary Key | Foreign Keys | Key Attributes & Constraints |
|:---|---:|:---|:---|:---|
| **`users`** | 10,000 | `user_id` | *None* | `age`, `gender`, `occupation`, `marital_status` |
| **`restaurants`** | 1,000 | `restaurant_id` | *None* | `restaurant_name`, `city`, `cuisine`, `rating` (0.0–5.0), `is_cloud_kitchen` (0/1) |

| **`order_items`** | 1,667,399 | `order_item_id` | `order_id` &rarr; `orders`<br>`menu_id` &rarr; `menu` | `quantity` (> 0), `price` (>= 0.00) |
| **Total Scale** | **2,294,057** | — | — | **100% referential integrity across all relationships** |

## 4. The End-to-End ETL Pipeline

The ETL pipeline transforms unstructured raw CSV files into an audited, indexed PostgreSQL analytical warehouse.

### Phase 1: Extraction & Ingestion
- **Script:** `src/ingestion/profile_data.py`
- **Execution:** Reads raw CSVs from `data/raw/`. If the raw CSVs are not uncompressed, it automatically detects and extracts `data/raw/Swiggy_Data.zip`.
- **Output:**
  - `data/processed/profiling_summary.csv`: Summary of row counts, column counts, missing cells, and key uniqueness across all 5 tables.
  - `data/processed/column_profile.csv`: Detailed per-column data types, null rates, and min/max values.

### Phase 2: Automated Data Quality Gates (16 Checks)
- **Script:** `src/quality/validate_data.py`
- **Execution:** Enforces 16 automated assertions against raw data. If any check fails, the pipeline aborts to protect database integrity.
- **Output:** `data/processed/validation_report.json` (Pass rate: 16/16, 100%).

| # | Check Name | Target Column | Assertion Logic | Result |
|:---:|:---|:---|:---|:---:|
| 1 | FK: Orders &rarr; Users | `orders.user_id` | All `user_id`s in `orders` exist in `users.user_id` | **PASS** (0 orphans) |
| 2 | FK: Orders &rarr; Restaurants | `orders.restaurant_id` | All `restaurant_id`s in `orders` exist in `restaurants.restaurant_id` | **PASS** (0 orphans) |
| 3 | FK: Menu &rarr; Restaurants | `menu.restaurant_id` | All `restaurant_id`s in `menu` exist in `restaurants.restaurant_id` | **PASS** (0 orphans) |
| 4 | FK: Items &rarr; Orders | `order_items.order_id` | All `order_id`s in `order_items` exist in `orders.order_id` | **PASS** (0 orphans) |
| 5 | FK: Items &rarr; Menu | `order_items.menu_id` | All `menu_id`s in `order_items` exist in `menu.menu_id` | **PASS** (0 orphans) |
| 6 | Price Boundary | `menu.price` | `price >= 0.00` | **PASS** |
| 7 | Order Amount Boundary | `orders.total_amount` | `total_amount >= 0.00` | **PASS** |
| 8 | Item Price Boundary | `order_items.price` | `price >= 0.00` | **PASS** |
| 9 | Strictly Positive Quantity | `order_items.quantity` | `quantity > 0` (no 0 or negative items) | **PASS** |
| 10 | Order Date Format | `orders.order_date` | Valid ISO `YYYY-MM-DD` | **PASS** |
| 11 | Delivery Time Format | `orders.delivery_time` | Valid 24-hour clock time `HH:MM:SS` | **PASS** |
| 12 | Restaurant Rating Boundary | `restaurants.rating` | Rating in `[0.0, 5.0]` | **PASS** |
| 13 | Veg Binary Flag | `menu.is_veg` | Value is in `{0, 1}` | **PASS** |
| 14 | Cloud Kitchen Flag | `restaurants.is_cloud_kitchen` | Value is in `{0, 1}` | **PASS** |
| 15 | Order Status Enum | `orders.order_status` | Value is in `{'Delivered', 'Cancelled'}` | **PASS** |
| 16 | Payment Method Enum | `orders.payment_method` | Value is in valid payment methods | **PASS** |

### Phase 3: Transformation & Standardization
- **Script:** `src/transform/transform_data.py`
- **Execution:**
  - Strips leading and trailing whitespace from string columns.
  - Normalizes text casing (title-cases restaurant names, cities, categories, cuisines).
  - Validates and standardizes date formats into ISO `YYYY-MM-DD`.
  - Ensures boolean flags are stored as clean integers (`0` or `1`).
  - Deduplicates records on primary keys.
- **Output:** Writes clean canonical CSVs and `data/processed/transformation_summary.json`.

### Phase 4: High-Performance Database Loading (Bulk COPY)
- **Script:** `db/load/load_data.py`
- **Execution:**
  1. Executes `db/schema/001_create_tables.sql` to establish relational DDL with constraints.
  2. Ingests data in topological order to satisfy foreign key dependencies:
     `users` &rarr; `restaurants` &rarr; `menu` &rarr; `orders` &rarr; `order_items`.
  3. Uses PostgreSQL binary streaming `COPY ... FROM STDIN` via `cur.copy_expert()`: loads **2,294,057 rows in under 25 seconds**.
  4. Executes `db/schema/002_indexes.sql` to build performance B-Tree and composite indexes:
     - `idx_orders_user_id` on `orders(user_id)`
     - `idx_orders_restaurant_id` on `orders(restaurant_id)`
     - `idx_orders_order_date` on `orders(order_date)`
     - `idx_orders_status_date` on `orders(order_status, order_date)`
     - `idx_order_items_order_id` on `order_items(order_id)`
     - `idx_order_items_menu_id` on `order_items(menu_id)`

## 5. Analytics Contract & SQL Modeling

Downstream consumer applications (Streamlit dashboard and NLQ) **never query raw base tables directly**. All calculations read exclusively from tested views and stored functions defined in `sql/analytics/`.

### Core Business Rules & Ground Truth Reconciliation

1. **Qualifying Order Definition:**
   Only orders with `order_status = 'Delivered'` qualify as completed orders. Cancelled orders (4.95%) contribute **₹0.00** to qualifying revenue.
2. **Exact Revenue Reconciliation:**
   Across all 600,000 orders, `orders.total_amount` equals `SUM(order_items.quantity * order_items.price)` with **zero differences**. Order-level revenue and item-level revenue agree down to the penny.
3. **Non-Additive Ratios:**
   Metrics like Average Order Value (AOV) and cancellation rates cannot be summed across days or months. For any arbitrary date selection, the dashboard calls `fn_kpi_summary(start_date, end_date)` to dynamically recompute true weighted ratios.
4. **Join Safety:**
   The base view `v_orders_enriched` pre-aggregates order items *before* joining to orders, ensuring order counts are never multiplied by line items.

| Metric | Ground Truth Value |
|:---|---:|

| Delivered (Qualifying) Orders | 570,281 (95.05%) |
| Cancelled Orders | 29,719 (4.95%) |
| Total Qualifying Revenue | **₹396,159,910.39** |

### Pre-Aggregated Views & Stored Functions

| SQL Object | Type | Grain | Purpose |
|:---|:---:|:---|:---|
| `v_orders_enriched` | View | 1 row per order (600k rows) | Core order view with pre-aggregated line items and restaurant metadata. |
| `v_order_items_enriched` | View | 1 row per item (1.66M rows) | Detailed line-item view with dish name, category, cuisine, and qualifying flag. |
| `v_kpi_overall` | View | 1 row | Lifetime platform KPI totals and benchmarks. |
| `v_kpi_daily` | View | 1 row per day | Daily time-series of orders, qualifying orders, revenue, and cancellation rate. |
| `v_kpi_monthly` | View | 1 row per month | Monthly aggregations for executive reporting and run-rates. |
| `fn_kpi_summary(start, end)` | Function | 1 row | Computes exact non-additive KPIs for any custom date range. |
| `fn_top_restaurants(start, end, limit)` | Function | N rows | Returns top restaurants by revenue for any period. |
| `fn_top_items(start, end, limit)` | Function | N rows | Returns best-selling menu items by units sold for any period. |
| `v_q01` to `v_q10` | Views | Various | Pre-built views answering 10 primary business questions (status mix, basket size, cuisine performance, hourly order patterns, city revenue, etc.). |

### Analytics User Security Grants
- Defined in `sql/analytics/90_grants.sql`.
- Creates a dedicated read-only role `foodflow_analytics`.
- Grants `SELECT` and `EXECUTE` access **only** on approved views and analytical functions. Direct table access to base tables (`orders`, `users`, etc.) is revoked.

## 7. Safe Natural Language Query (NLQ) Engine

"Ask FoodFlow AI" allows non-technical business users to ask questions in plain English (e.g., *"Top 5 restaurants by revenue in June 2025"* or *"What is our monthly cancellation rate?"*) and receive verified results in seconds.

### Dual-Mode Architecture (Claude LLM & Offline Rule Engine)

- **LLM Mode (Online):** When an `ANTHROPIC_API_KEY` is provided in `.env`, queries are routed to Anthropic Claude (Claude 3.5 Sonnet / Haiku). The prompt (`nlq/prompt.py`) is injected with the analytics contract schema catalog (`nlq/schema_context.md`) and few-shot examples.
- **Rule-Based Engine (Offline):** When no API key is configured, FoodFlow automatically falls back to an offline rule-based parser (`nlq/rules.py`). It parses common analytical intents (top restaurants, best sellers, cancellation rates, monthly revenue, cuisine breakdowns) using regex patterns, allowing 100% functionality without external API dependencies.

### 5-Tier Security Guardrails & Allowlist

```
User Query: "Top 5 restaurants by revenue in 2025"
     │
     ▼
[ Tier 1: Pre-Screening Regex Guard ] ──> Blocks DDL/DML (DROP, DELETE, INSERT, UPDATE, ALTER)
     │                                ──> Blocks unanswerable topics (driver speed, rider distance)
     ▼
[ Tier 2: Translation Layer (Claude / Rules) ] ──> Generates single SELECT statement on approved views
     │
     ▼
[ Tier 3: AST & SQL Safety Validator ] ──> Verifies starts with SELECT or WITH
     │                                 ──> Rejects multiple statements (semicolons) & comments
     │                                 ──> Enforces View Allowlist (v_kpi_*, fn_top_*, v_orders_enriched)
     │                                 ──> Rejects raw base tables (orders, users) & pg_* catalogs
     ▼
[ Tier 4: Read-Only Database Execution ] ──> Dedicated user 'foodflow_analytics'
     │                                   ──> Enforces 10-second query timeout (statement_timeout = 10000)
     │                                   ──> Enforces 500-row result cap
     ▼
[ Tier 5: Auditable Result Presentation ] ──> Formatted table + "Show SQL" inspection container
```

## 8. Dataset Nuances & Boundaries (Honest Notes)

To prevent misleading analytics, the following dataset realities are formally documented in the schema and enforced by the NLQ engine:

1. **No Courier / Driver Data:**
   The dataset contains no driver or delivery partner entities. Questions asking for driver speed, transit distance, or delivery agent performance cannot be answered and are rejected gracefully.
2. **Delivery Time is a Clock Timestamp:**
   The `delivery_time` column records the clock timestamp of the order (e.g., `19:45:00`), not an elapsed duration in minutes. Elapsed transit time cannot be computed from this field.
3. **Repeat Customer Distribution:**
   Every customer in the dataset has placed at least 2 orders. Rather than a binary "new vs. repeat" metric, customer frequency distributions (orders per user) are used.
4. **Currency Representation:**
   The dataset stores numeric currency amounts. Amounts are displayed as standard monetary values.

## 9. Step-by-Step Installation & Setup Guide

### Prerequisites
- **Python:** Version 3.10 or higher.
- **PostgreSQL:** Version 14 or higher (running locally or via Docker).
- **Git:** Installed on your machine.

---

### Step 1: Clone the Repository & Setup Environment
```bash
# Clone the repository
git clone https://github.com/Abikrishnanms/data_engineering_food_analytitcs_platform.git
cd data_engineering_food_analytitcs_platform

# Create virtual environment
python -m venv .venv

# Activate virtual environment
# Windows (PowerShell):
.venv\Scripts\Activate.ps1
# Windows (CMD):
.venv\Scripts\activate.bat
# Linux / macOS:
source .venv/bin/activate

# Install all dependencies
pip install -r requirements.txt
```

---

### Step 2: Database Configuration
Copy `.env.example` to `.env` in the root directory:
```bash
# Windows (PowerShell):
Copy-Item .env.example .env
# Linux / macOS:
cp .env.example .env
```

Open `.env` and configure your local PostgreSQL credentials:
```ini
# PostgreSQL Connection Configuration
FOODFLOW_DB_HOST=localhost
FOODFLOW_DB_PORT=5432
FOODFLOW_DB_NAME=foodflow
FOODFLOW_DB_USER=postgres
FOODFLOW_DB_PASSWORD=your_postgres_password

# Analytics Role (created automatically by sql/analytics/90_grants.sql)
FOODFLOW_ANALYTICS_USER=foodflow_analytics
FOODFLOW_ANALYTICS_PASSWORD=analytics_read_only_pw

# Optional Anthropic API Key (free rule-based fallback used if left blank)
ANTHROPIC_API_KEY=
```

---

### Step 3: Run the Data Quality & ETL Pipeline
Run the three data engineering pipeline scripts to profile, validate, and clean the raw data:
```bash
# 1. Profile raw CSV datasets
python src/ingestion/profile_data.py

# 2. Run automated quality gates (16 checks)
python src/quality/validate_data.py

# 3. Clean, normalize, and export canonical CSVs to data/processed/
python src/transform/transform_data.py
```

---

### Step 4: Create Database, Bulk Load Data & Build Analytics Layer
1. In PostgreSQL, ensure the target database `foodflow` exists:
```sql
CREATE DATABASE foodflow;
```

2. Run the high-performance bulk loader to create tables and load all 2.29M+ records:
```bash
python db/load/load_data.py
```

3. Deploy the analytics views, functions, and security grants using `psql`:
```bash
psql -h localhost -U postgres -d foodflow -f sql/analytics/01_base_views.sql
psql -h localhost -U postgres -d foodflow -f sql/analytics/10_kpis.sql
psql -h localhost -U postgres -d foodflow -f sql/analytics/20_business_questions.sql
psql -h localhost -U postgres -d foodflow -f sql/analytics/90_grants.sql
```

---

### Step 5: Run Automated Tests
Verify that the database constraints, analytical reconciliations, and NLQ safety rules pass:
```bash
# 1. Database schema and row-count verification
python tests/run_tests.py

# 2. SQL analytics reconciliation suite (29 tests)
psql -h localhost -U postgres -d foodflow -f tests/test_analytics.sql

# 3. NLQ safety and translation test suite (30 tests)
python -m pytest tests/test_nlq.py
```

---

### Step 6: Launch the Streamlit Dashboard
Start the interactive analytics application:
```bash
streamlit run app/Home.py
```

Open your browser at **`http://localhost:8501`** to explore the dashboard.
